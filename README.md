# 商场柜台租金阶梯

供商业运营结算员核对每个柜台的月度保底、累进抽成、旧期回冲和缴款记录。内置两份练习账簿，包含合同交叠、退单超过原款、重复收银等问题。上传可使用相同的 JSON 结构。

## 启动与演示

1. 运行 `docker compose up --build -d`，打开 `http://127.0.0.1:18434/`。
2. 选择「南馆核对样例」并运行 2026-11，核对柜台 001 的本期应计 180 元、历史调整 −20 元和实缴 160 元。
3. 切到「退单回冲」，从原销售账期追查两次计算及退单号。回到「租金勾稽」查看收缴差额。
4. 选择「北馆十一月」重跑，到「收银采信」按原因码复核隔离记录。
5. 从顶部下载结算凭证，或在「租金勾稽」打印月结联。
6. 打开「停业补偿」，选择「东区改造停业告知」生成结果：101、102 可发布，103 参考期销售不完整、104 合同重叠、105 合同空档，三个柜台挂起。补偿池 2,000 元按可复核损失比例分配，101 得 1,250 元、102 得 750 元，合计不突破池。页面同时给出「按保底份额」对照列，可看到按租金份额分配会让低销售柜台多拿。

## 接口与测试

`POST /api/runs` 接受 `sample` 和 `period`。也可以用 multipart 表单附带 JSON 文件 `file`。响应包含运行编号、复用标记和勾稽数。`GET /api/runs` 返回最近 40 个批次，其余入口列于深度登记。

停业补偿使用 `POST /api/closure/runs`，接受 `sample=east`，或 multipart 同时上传账簿 `file` 与停业告知 `notice`。`GET /api/closure/{id}` 返回补偿结果，`GET /api/closure/notice/{告知号}/versions` 返回该告知的版本链。同一告知重复运行不新增补偿，新账簿会取代旧版本；计算失败保留旧版。

运行 `docker compose exec -T app pytest -q` 验证。`docker compose down` 停止服务并保留运行历史。需要重新开始演示时，可备份运行记录后使用新的 Compose 项目名启动独立数据卷。
